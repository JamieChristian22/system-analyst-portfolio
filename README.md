# 🏥 Featured Systems Analysis Case Study

## Healthcare Appointment Management System

### Business Problem

A simulated outpatient healthcare organization relied heavily on telephone-based appointment scheduling.

Scheduling staff manually:

- Verified patients
- Searched provider calendars
- Identified available appointment slots
- Entered appointments
- Managed cancellations
- Contacted patients with reminders
- Maintained waitlists
- Coordinated scheduling changes
- Reconciled scheduling information

This created several operational problems:

- Long patient scheduling wait times
- Booking errors
- Appointment conflicts
- High administrative workload
- Excessive no-shows
- Manual reminder processes
- Limited patient self-service
- Weak system auditability
- Fragmented payment processing
- Limited provider-utilization visibility

---

# 🎯 Business Objectives

The system modernization initiative established the following objectives:

1. Enable secure patient self-service scheduling.
2. Reduce appointment booking errors.
3. Reduce scheduling wait times.
4. Reduce appointment no-shows.
5. Automate appointment reminders.
6. Reduce staff administrative workload.
7. Improve provider-schedule visibility.
8. Strengthen appointment auditability.
9. Integrate secure payment authorization.
10. Improve operational reporting.
11. Establish role-based system access.
12. Improve production monitoring.
13. Create structured production-support processes.

- Successful appointments generate confirmation events.

# 📖 Business Rules

Key business rules include:

- Provider slots must remain unique by provider, location, start time, and service.
- Appointment duration is determined by service type.
- New-patient visits require identity verification.
- Same-day cancellations require a reason code.
- Waitlist ranking considers urgency, requested date, and enrollment time.
- Reminder channels follow patient communication preferences.
- Full payment card numbers are never stored.
- Staff overrides require authorized roles and justification.
- Cancelled slots become available only after transaction completion.
- Audit events are immutable to standard application users.

# 📝 User Stories & Acceptance Criteria

### Patient Appointment Search

**As a patient, I want to search available appointments so that I can select a convenient date and time.**

**Acceptance Criteria**

- Only eligible slots are displayed.
- Location, provider, service, and date filters are supported.
- Search results meet the approved performance requirement.

### Patient Appointment Booking

**As a patient, I want to book an appointment online so that I do not need to call the scheduling office.**

**Acceptance Criteria**

- Patient identity is validated.
- Selected slot is temporarily held.
- Business rules are evaluated.
- Payment is authorized when required.
- Appointment ID is generated.
- Confirmation is displayed.
- Notification event is generated.
- Audit event is recorded.

### Staff-Assisted Booking

**As a scheduler, I want to book appointments for patients so that I can assist patients who contact the scheduling department.**

**Acceptance Criteria**

- Scheduler must have the required role.
- Patient identity is selected.
- Standard booking validation applies.
- Scheduler identity is captured in the audit trail.

- Confirmed bookings cannot be created reliably.
- Data integrity is at risk.

2. Enter controlled maintenance mode.
3. Stop background consumers.
4. Restore prior application release.
5. Reverse compatible database changes or restore approved backup.
6. Re-enable previous scheduling workflow.
7. Validate control totals.
8. Communicate operational status.
9. Create incident record.

## Example Incident

**Incident:** INC-2026-017  
**Severity:** P2

### Problem

A subset of confirmed appointments did not receive SMS confirmation during a simulated 43-minute external provider disruption.

### Impact

- 64 appointments affected
- Appointments remained confirmed
- Email confirmations continued where available
- No appointment data was lost

### Root Cause

The external SMS provider experienced elevated timeout rates. Application retry behavior retried too aggressively during the degraded period.

### Corrective Actions

1. Implement exponential backoff.
2. Add jitter.
3. Add circuit-breaker behavior.
4. Add provider-health monitoring.
5. Update operational runbook.
6. Add regression testing for sustained timeouts.
7. Monitor delivery performance by communication channel.

# 🧠 Key Systems Analysis Principles Demonstrated

## Requirements Must Be Traceable

Requirements become more valuable when they connect directly to system components, interfaces, acceptance criteria, and test cases.

## Systems Analysts Bridge Business and Technology

Systems analysis requires understanding business outcomes while also analyzing applications, integrations, data, security, testing, and operational constraints.

## Nonfunctional Requirements Matter

A system is not successful simply because its functionality works.

Performance, availability, scalability, security, recovery, accessibility, and observability must also meet business expectations.

## Integrations Require Failure Analysis

Integration analysis must define both successful communication and expected system behavior when dependencies fail.

## Implementation Is Part of Systems Analysis

Production readiness, cutover, rollback, support, monitoring, and operational ownership should be considered before go-live.

## Production Incidents Create New Requirements

Root-cause analysis should feed improvements back into requirements, architecture, testing, monitoring, support, and system controls.
